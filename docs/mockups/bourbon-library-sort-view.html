Sort & View Options for the Bourbon Library

A Card / List view switch and a Sort dropdown for the library's main grid, sitting just above the results — the same spot the Parent Company browse view's own search+sort toolbar already established. All 279 real library entries are loaded below, so every sort genuinely reorders real data: try Most Corn % and Most Wheat % to see it surface the mellow, near-100%-corn bourbons and the classic wheated recipes (Weller, Maker's Mark) respectively. Whichever field you're sorting by shows up as a small metric chip on every card/row, in both views — not just the order, the number behind it.

Design notes

Reused, not reinvented

The view switch is the same .preview-toggle/.toggle-btn segmented control Live Preview's Current Talker/Full Page switch already uses. The sort control is the app's existing .field-select dropdown (every form field in the app already looks like this), not a bare native <select>. List rows reuse .bourbon-list/.bourbon-row from the Parent Company drill-down verbatim, just with a metric slot and chevron added.

Grain sorts go by family, not literal string

Classic wheated bourbons (Weller, Maker's Mark) record their secondary grain as "Red Winter Wheat", not "Wheat" — a literal-string "Most Wheat" sort would have silently missed every one of them. Most Corn/Rye/Wheat/Malted Barley % each sum every grain-family variant in the library's real data (e.g. Wheat + Malted Wheat + Red/Texas Winter Wheat) before sorting.

Sort options, grouped

  • Alphabetical — Name A–Z / Z–A, Distillery A–Z
  • Confidence — Confirmed first, Needs verification first
  • Grain % — Most Corn, Most Rye, Most Wheat, Most Malted Barley
  • Recipe — Simplest (fewest grains) / Most complex (most grains) — surfaces Rabbit Hole Cavehill's 4-grain "triple malt" recipes at one end and standard 2-grain ryes at the other
  • SKU — Low–High, for cross-checking against a printed POS list in SKU order

Other recommendations (not built into this mockup)

Remember the last-picked view and sort per PC (localStorage), the way Full Page/Current Talker's own choice already persists, so staff don't reselect List + Most Rye every time they open the Library. Card view could keep the plain grain bar as-is and let the metric chip carry the sort context, exactly as done here, so this doesn't compete with the separate Mash Bill donut chart work on the profile page.
