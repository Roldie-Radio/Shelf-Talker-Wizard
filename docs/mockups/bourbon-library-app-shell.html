Bourbon Library App Shell

✅ Decided: Sidebar Rail

Of the three entry points compared last round, Sidebar Rail is the pick — a persistent icon rail down the left edge of the whole app, with Bourbon Library as one first-class icon alongside the app's existing screen rather than a tab switch or a header button. Everything the existing wizard already does — Manual Entry / Import / Search, the Queue side panel, History, and Settings — stays together under one Shelf Talker icon, reached exactly the way each piece is reached today (Queue as the panel next to the form, History and Settings as buttons that open their own dialogs). The rail itself only ever adds one new thing: Bourbon Library.

This version wires the rail up for real: click between Shelf Talker and Library to swap the content pane. Open Settings from inside Shelf Talker and flip Bourbon Shelf Talkers off, then check the form behind it and the Library icon — one changes, the other doesn't.

Design notes

The rail only ever needed two icons

Queue is already a side panel on the same screen as the form, History is already a button that opens a dialog, and Settings is already a menu item that opens a dialog too — none of the three is a separate top-level screen today, so none needed its own rail icon. Everything the existing wizard does stays together under one Shelf Talker icon (renamed from an earlier "Build"); the rail adds exactly one new thing, Library.

Shelf Talker view now shows Queue, History & Settings in place

The mock content pane puts the Queue panel back on the right and a History button back near the tabs, right where both live in the real app today, and adds a Settings… button next to History that opens a dialog — matching the real app's own Settings… menu item rather than inventing a new pattern. Nothing about any of the three changes, only the outer chrome around the whole screen (the new rail on the left) does.

Decoupling, now shown where the flag actually lives

Last round's mockup floated the Experimental Features switch next to the entry-point comparison. Here it sits inside the real Settings dialog, opened from inside Shelf Talker exactly like it is today — flip it off, and only the Shelf Talker form's Mash Bill / Nose-Palate-Finish fields react live underneath. The Library rail icon, its content, and its own confidence filters are untouched, because they never read that flag to begin with.

Open questions

  • Does "Add a bourbon" belong in the Library itself now (a real add-entry flow, not just the Edit Talker form's "Save this mash bill" checkbox), now that it's meant to stand on its own as a reference?
  • Storage/sync stays exactly as designed for the Mash Bill Library (Server-PC-hosted, every register polls) — this is presentation only, not a new data architecture.
  • Card grid vs. table for Browse: grid reads more "reference app," but a dense table scales better past a few dozen entries. Worth revisiting once real shelf data is seeded in.
