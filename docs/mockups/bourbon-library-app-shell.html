Bourbon Library App Shell

✅ Decided: Sidebar Rail

Of the three entry points compared last round, Sidebar Rail is the pick — a persistent icon rail down the left edge of the whole app, with Bourbon Library as one first-class icon alongside the app's existing screen rather than a tab switch or a header button. Manual Entry / Import / Search, the Queue side panel, and History all stay together under one Shelf Talker icon, reached exactly the way each is reached today. Settings keeps its own rail icon rather than nesting inside Shelf Talker — a standing destination for the one screen most likely to get more settings over time, not just a single menu item.

Both new icons are drawn rather than emoji: Shelf Talker is a tiny rendering of an actual printed talker, and Bourbon Library is a Glencairn glass, partly filled — the shape whiskey gets nosed and tasted from, standing in for the whole reference idea. Click between Shelf Talker, Library, and Settings to swap the content pane. Flip Bourbon Shelf Talkers off in Settings, then check the Shelf Talker tab and the Library icon — one changes, the other doesn't.

One thing earlier versions left out entirely: the real app also has a Windows-style menu bar (File / Tools / Advanced / Help, above the app bar) that never appeared in this mockup. File and most of Tools are Queue/talker-specific and clearly belong nested inside Shelf Talker, same as everything else — but Advanced (Export File Settings, Server PC) and Help (What's New, About) are app-wide, not talker-specific, and now that Settings has its own rail icon there's a real choice about where they land. The toolbar below compares both; open File/Tools/Advanced/Help in the Shelf Talker view to see what's actually in each one.

Design notes

Queue and History fold in; Settings keeps its own icon

Queue is already a side panel on the same screen as the form, and History is already a button that opens a dialog — neither is a separate top-level screen today, so neither needed its own rail icon; both stay nested inside Shelf Talker (renamed from an earlier "Build"). Settings gets its own rail icon back rather than folding in too — it's the one screen most likely to grow more settings over time, and staff reaching for it shouldn't have to go through Shelf Talker to get there.

Two icons drawn from the product, not picked from an emoji set

Shelf Talker is a tiny rendering of an actual printed talker — white card, dark border, red price block, using the same --ink/--sale-red print colors the real cards use. Library is a Glencairn glass, partly filled with amber liquid clipped to the glass's own outline — the nosing glass shape, standing in for "everything we know about what's in the bottle." Both read as the product itself rather than a generic tool/book icon.

Decoupling, now shown where the flag actually lives

The Experimental Features switch sits on its own Settings screen, reached from its own rail icon — flip it off, then switch to Shelf Talker and only the Mash Bill / Nose-Palate-Finish fields react. The Library icon, its content, and its own confidence filters are untouched, because they never read that flag to begin with.

Menu bar: not yet decided, shown both ways

File and Tools are Queue/talker-specific (Open/Save/Find Queue, Beer Talker Info, Wine Pairing Rules) and stay nested inside Shelf Talker either way — Mash Bill Library and Settings both already dropped out of Tools since they have rail icons now. Advanced (Export File Settings, View Export File, Server PC) and Help (What's New, Check for Updates, About) are the open part: app-wide, not talker-specific, so there's a real argument for moving them into Settings now that Settings is a first-class destination rather than a menu item. Toggle the comparison switch above the rail to see both; no default picked yet.

Open questions

  • Menu bar: keep Advanced/Help nested in Shelf Talker, or move them into Settings (see above) — still open.
  • Does "Add a bourbon" belong in the Library itself now (a real add-entry flow, not just the Edit Talker form's "Save this mash bill" checkbox), now that it's meant to stand on its own as a reference?
  • Storage/sync stays exactly as designed for the Mash Bill Library (Server-PC-hosted, every register polls) — this is presentation only, not a new data architecture.
  • Card grid vs. table for Browse: grid reads more "reference app," but a dense table scales better past a few dozen entries. Worth revisiting once real shelf data is seeded in.
