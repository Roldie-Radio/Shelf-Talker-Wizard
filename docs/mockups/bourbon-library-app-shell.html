Bourbon Library App Shell

Confirmed direction: Bourbon Shelf Talkers (the mash bill chip builder, Nose/Palate/Finish fields, and Store Pick ribbon on an actual talker) stays exactly where it is today, gated behind Settings → Experimental Features. The Bourbon Library — the browsable reference built on bourbon-profile-page.html — is the part coming out from under that toggle and out from Tools…, into something that reads as its own space within the program rather than a management dialog for a talker-building feature. This mockup proposes how it gets there: where the entry point lives, and what the Library looks like once you're inside it.

A distinct dark "reading room" band (vs. the light, form-heavy Talker Builder) signals the shift without leaving the app — same fonts, same corner radii, same gold accent family, just a different room. Design notes

Recommendation: Top Nav Tab

Reads most clearly as "a second app living here" while reusing a pattern staff already know from switching workspaces in other tools. Sidebar Rail is the most scalable if more standalone reference tools show up later, but it restructures the entire app shell to get there — a bigger change than this one feature justifies today. Header Launcher is the smallest change but reads as "one more button," not a separate space — weakest fit for what was actually asked for.

Decoupled from the experimental flag on purpose

Bourbon Shelf Talkers stays experimental because it changes what prints on a real, customer-facing talker — that's still worth gating. The Library is read-only staff reference; nothing about browsing it affects a printed sign. Tying its visibility to an unrelated print-feature flag was never really about risk, just an accident of where the data happened to live first.

Confidence filter chips are a real staff workflow, not decoration

"Needs verification" surfaces exactly the Estimated/Unknown entries from the Mash Bill Confidence work — a standing to-do list of what's worth researching next, for free, out of data the Library already has. Worth keeping as a real filter rather than trimming it in an actual build.

Open questions

  • Does "Add a bourbon" belong in the Library itself now (a real add-entry flow, not just the Edit Talker form's "Save this mash bill" checkbox), now that it's meant to stand on its own as a reference?
  • Sync/storage stays exactly as designed for the Mash Bill Library (Server-PC-hosted, every register polls) — the app-shell change here is presentation only, not a new data architecture.
  • Card grid vs. table for Browse: grid reads more "reference app," but a dense table scales better past a few dozen entries. Worth revisiting once real shelf data is seeded in.
