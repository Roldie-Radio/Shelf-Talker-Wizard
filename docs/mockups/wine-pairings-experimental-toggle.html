Wine Food Pairings, Gated Behind Settings → Experimental Features

Same suggestion engine as the earlier Food Pairing Suggestions mockup — unchanged here — now scoped as an opt-in experimental feature instead of shipping on by default. This targets the 2.6 branch, which already has an “Experimental Features” section in the Settings modal (currently empty — “Nothing to turn on yet”); this would be its first entry.

  • A new toggle switch labeled Wine Food Pairings is added under Settings → Experimental Features, below the existing Change Theme / Menu Bar Size rows. Off by default.
  • While off, the Edit Talker form shows no pairing fields at all — not collapsed, not disabled, just absent, same as the form looks today. The Pairing Rules panel doesn't render, and no talker prints a “Pairs Well With” block. Click the switch below to see all three appear live.
  • No breadcrumb or hint is shown on the form itself pointing at the setting, to match “not visible unless this toggle is on” literally — discovery is Settings only, the same as any other opt-in preference in that modal. Say the word if a subtle pointer to Settings is wanted instead.
  • The toggle's state would persist per device via localStorage (a new shelfTalkerExperimentalWinePairings.v1 key), the same convention THEME_KEY/ACCENT_KEY/MENU_SIZE_KEY already use in app.js.
  • Static mockup only — not wired into the real Settings modal, Edit Talker form, or print CSS.

Experimental Features

Wine Food Pairings Suggests up to 3 food pairings on Wine / Spirits talkers, based on the varietal detected in the Product Title/Description. Adds a Food Pairing Suggestions section to Edit Talker when on.

Experimental features are off by default, may change or be removed without notice, and are saved per device.
